# BRIEF — Стоп-звонки (CallGuard)

Краткий бриф по проекту и текущей итерации. Обновляется по ходу работы.

## Что это

Android-приложение, которое сбрасывает входящие звонки с номеров, которых нет в
адресной книге, и ведёт журнал решений. Работает локально, без сервера.

## Текущее состояние (1.10)

- `CallScreeningService` + роль «Фильтрация вызовов», minSdk 29 (Android 10+).
- Журнал всех решений, пауза, расписание, белый список, диагностика.
- Автообновление через GitHub Releases, установка через content-URI.
- Номера нормализуются через ICU с учётом страны.
- Сайт: `docs/index.html` (GitHub Pages), релизы v1.5–v1.10, Boosty.

## Итерация 1.11 — требования

1. **Английская локализация приложения.** Английский — язык по умолчанию
   (`values/`), русский — `values-ru/`. Все ключи обязаны присутствовать в обоих
   файлах: отсутствие строки в default ломает английскую локаль.
2. **Английская версия страницы проекта** (`docs/en/index.html`) и `README.en.md`,
   переключатель языка на обеих страницах.
3. **Индикатор работы.** Постоянное тихое уведомление «Фильтр активен» (или «Пауза
   до …»), тап открывает приложение. Обновляется при изменении настроек, после
   каждого звонка и после перезагрузки телефона (`BOOT_COMPLETED`). Требует
   `POST_NOTIFICATIONS` (Android 13+) и `RECEIVE_BOOT_COMPLETED`.
4. **Копирование номера** из журнала долгим нажатием на строку → в буфер обмена
   + тост.

## Ограничения

- Без AndroidX: только framework API, сборка `build-apk.ps1` (aapt2/javac/d8).
- Русский — язык общения и UI по умолчанию для русской локали; код и коммиты —
  на английском.
- Не ломать существующие тесты (`tools/PhoneNumbersSelfTest`,
  `tools/ScheduleSelfTest`) и формат данных (БД v2).

## Критерии готовности

- Сборка проходит, `apksigner verify` — Verifies, versionCode 12.
- Наборы строк в `values/` и `values-ru/` совпадают (проверено скриптом).
- Уведомление появляется при включённом фильтре и исчезает при выключении.
- Долгое нажатие в журнале кладёт номер в буфер.
- Страница `/en/` открывается, переключатель языка работает в обе стороны.

## Процесс перед релизом (правило)

Релиз не выпускается сразу после написания кода. Перед каждым релизом:

1. **Вспомнить, над чем работали** — перечитать дифф последних коммитов, а не
   только последнюю правку.
2. **Проверить реализацию** — пройти по изменённым классам и краевым случаям:
   пустые данные, нули и деление, границы периодов, старые настройки, отсутствие
   разрешений, поведение после перезагрузки и обновления.
3. **Проверить UI** — по реальным размерам из layout: переносы длинных подписей,
   узкие экраны (320 dp), увеличенный системный шрифт, обе темы, состояния
   «выключено / активно / недоступно». Для проверки рисовать мокап по тем же
   размерам (`tools/render_*.py`).
4. **Написать список замечаний** с приоритетами и рекомендациями по исправлению.
5. **Исправить и проверить заново** — сборка, самотесты, повторный рендер.
6. **Только после этого спросить пользователя про релиз**, показав, что
   проверено и что осталось известным ограничением.

Нельзя предлагать релиз, пока не выполнен пункт 4: найденные замечания либо
исправлены, либо явно вынесены в «известные ограничения» с согласием пользователя.
